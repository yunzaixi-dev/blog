先说结论：今晚 Codex 的速度还可以，拿来当 Claude 的**廉价替代**够用了。注意，只是廉价替代，不是平替。

## 一次请求的数据

下面是我在自己的网关面板上看到的一次请求，不是跑分，只是随手一条：

| 项目 | 数值 |
| --- | --- |
| 输入 token | 4,324 |
| 输出 token | 1,183 |
| 缓存 token | 140.5K |
| 费用 | $0.034532 |
| 首字延迟 | 4.88 s |
| 总耗时 | 25.85 s |
| 输出速度 | 45.8 tok/s |

![一次 Codex 请求在网关面板上的 token、费用和延迟](/codex-cheap-claude-alt/panel.jpg)

## 怎么看这组数字

- **速度**：首字将近 5 秒不算快，但出字之后 45.8 tok/s 很稳，一千多 token 的回复 26 秒左右写完，不卡人。
- **价格**：这条请求带了 140.5K 的缓存，实际只花了约 3.5 美分。长上下文反复来回的场景，缓存命中对账单很友好。
- **样本**：只有一条，还是今晚的网络和负载，换个时段可能完全不同。

## 为什么只说廉价替代

我没有做系统对比，所以这里只说感受层面的东西：速度和价格让它**可以顶上**，需要高质量输出或者复杂改动的时候，我还是会回到 Claude。Codex 的位置，就是便宜、够快、能干活的备选。

如果之后有更多时段的数据，我再补一篇。
